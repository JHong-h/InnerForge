## Project

InnerForge is a Tauri 2 desktop app for personal reflection and AI-powered analysis. React 19 + TypeScript frontend, Rust backend, SQLite database.

## Commands

```bash
pnpm dev          # Start Vite dev server (port 1420)
pnpm build        # TypeScript check + Vite production build
pnpm tauri dev    # Run full Tauri app in dev mode
pnpm tauri build  # Build distributable desktop app
```

## Architecture

**Frontend** (`src/`): React + Vite + Tailwind CSS + Zustand for state.

- `App.tsx` — React Router with routes: `/` (periods list), `/period/:id` (entries), `/period/:periodId/entry/:entryId` (editor), `/reports`, `/report/:id`, `/settings`
- `lib/store.ts` — Zustand store: periods, entries, reports, AI configs, UI state
- `lib/api.ts` — All Tauri `invoke()` calls to the Rust backend
- `components/` — Layout, Sidebar, Onboarding, MoodPicker, MarkdownPreview, etc.

**Backend** (`src-tauri/`): Rust with Tauri 2 plugin system.

- `lib.rs` — App setup, registers all command handlers
- `db.rs` — SQLite init with WAL mode, schema migrations
- `models.rs` — Serde-serialized structs shared with frontend
- `commands/` — Modular handlers:
  - `periods.rs` / `entries.rs` — CRUD for observation periods and daily entries
  - `ai_config.rs` / `ai_service.rs` — AI provider config and analysis (daily insight, period summary, restructure plan)
  - `reports.rs` / `skills.rs` / `export.rs` — Reports, skill tracking, data export

**Data flow:** React component → `api.ts` invoke → Tauri command → SQLite → response back through the chain.

## Key Patterns

- Path alias: `@/*` maps to `src/*` (configured in tsconfig.json and vite.config.ts)
- AI providers are configurable (OpenAI, Anthropic, custom endpoints) via settings
- Observation periods have lifecycle states: active → paused → completed → archived
- Entries support mood tracking and image attachments
- Reports are generated by AI analysis commands and stored in SQLite
- Theme: light/dark/system, managed in Zustand store
